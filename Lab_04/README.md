# Лабораторна робота №4: Рекурсія та мемоізація в Python (Варіант 4)

## Опис роботи
У лабораторній роботі реалізовано базові рекурсивні та ітеративні алгоритми, а також індивідуальне завдання за **варіантом 4** (рекурсивний та ітеративний бінарний пошук у відсортованій незмінній послідовності).

### Основні модулі
* `algorithms.py` — чистий рекурсивний `quicksort`, обходи бінарного дерева (`preorder`, `inorder`, `postorder`, `bfs_level_order`, `dfs_preorder_iter`), числа Фібоначчі (`fib` з `@lru_cache` та `fib_iter`), бінарний пошук (`binary_search_recursive`, `binary_search_iter`).
* `main.py` — точка входу для демонстрації роботи алгоритмів та заміру часу бінарного пошуку.
* `tests/` — набір тестів `pytest` для перевірки коректності, чистоти функцій, кешування та граничних випадків.

## Ліміт рекурсії CPython та відсутність TCO
* **Ліміт стеку:** за замовчуванням у CPython максимальна глибина стеку викликів становить ~1000 кадрів (`sys.getrecursionlimit()`). При перевищенні виникає `RecursionError`. Ручне підняття ліміту через `sys.setrecursionlimit()` є небезпечним, оскільки може призвести до переповнення системного стеку (Segfault).
* **Відсутність TCO:** CPython свідомо не реалізує оптимізацію хвостової рекурсії (Tail-Call Optimization), щоб зберігати повні та зрозумілі стектрейси. Через це кожен рекурсивний виклик створює новий кадр у стеку.
* **Коли ітерація безпечніша:** для дуже глибоких структур даних або високонавантажених циклів ітеративні алгоритми (як-от `binary_search_iter`, `fib_iter`, `bfs_level_order`, `dfs_preorder_iter`) працюють без накладних витрат на стек викликів і не ризикують отримати `RecursionError`.
